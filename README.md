Решение на основе предоставленного проекта. Производственные файлы в `src/` **не изменены**, исходные проверки (`assert`) и сценарии тестов сохранены. Вместо всех `...` добавлена настройка тестовых объектов либо запуск и остановка Java-сервера.

- `tests/ru/hse/client/TestServerlessAccountManagerAuth.py` — заглушки источника авторизации и проверка менеджера аккаунтов.

- `server/` — сервер курса и его библиотеки; **jar-файлы не входят в Git** (см. раздел «JAR-файлы учебного сервера»).

## Запуск

Требования: Python 3.10+, Java 21, свободный порт TCP 7000 и доступ к установке зависимостей Python.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
```

Если Java-сервер уже запущен вручную, вместо автоматического запуска можно указать `SERVER_URL` (например, `http://localhost:7000`), но серверное состояние тогда должно быть подготовлено отдельно.

## Как работают заглушки

В тестах с `unittest.mock.create_autospec` задаются ответы `OperationResponse`, соответствующие проверяемому сценарию. Для последовательностей `login → deposit → withdraw → get_balance` используется `BankStub`, в котором хранится баланс, учитывается активность сессии, проверяется её номер, успешные операции изменяют средства, а ошибочные — нет. `DataStub` использует ту же логику для тестирования класса `Account` без авторизации. Конфигурация ошибки для отдельного метода передаётся через `*_error`.

## Особенность исходного кода

В исходной реализации `AccountManager.call_register()` есть проверка `if answer and isinstance(answer, int)`. На первом запуске Java-сервер выдаёт допустимый нулевой ID сессии (`0`), и клиент отвергает его как ложное значение. Поскольку по условию изменять исходный код нельзя, системная фикстура **перед тестами создаёт техническую сессию**, чтобы два имеющихся теста проверяли рабочие номера сессий. Это ограничение исходной реализации, а не исправление её дефекта. Все изменения находятся только в тестовой настройке.

## JAR-файлы учебного сервера

Библиотеки курса в `server/` (`HomeTask04Java.jar` и зависимости) **не входят в
репозиторий**: права на их распространение не подтверждены. Для запуска двух
системных тестов положите jar-файлы курса в `server/` — без них эти два теста
завершаются ошибкой запуска Java-процесса, остальные 69 работают как обычно:

```bash
python -m pytest -q --ignore=tests/ru/hse/client/TestServerClientSystem.py   # без jar
python -m pytest -q                                                          # с jar и Java 21
```
