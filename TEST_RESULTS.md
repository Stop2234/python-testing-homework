## 6. Обнаруженные проблемы и ограничения окружения

Все перечисленные ниже пункты — особенности моей машины, а не проекта; они устранены
настройкой окружения, исходный код и тесты не менялись:

1. **Java отсутствовала в системе** (`java` не найден, `/usr/lib/jvm` пуст).
   `sudo` требует интерактивного пароля, поэтому пакет из apt не ставился. Установлен
   переносной Amazon Corretto OpenJDK 21.0.12.1 в `~/.local/opt/amazon-corretto-21.0.12.12.1-linux-x64`,
   добавлен в `PATH` только на время прогона. Версия соответствует требованию README (Java 21).
2. **`python3.14-venv` не установлен** (в системе нет `ensurepip`), из-за чего обычный
   `python3 -m venv .venv` падает. Окружение создано как `python3 -m venv --without-pip .venv`,
   затем pip 26.2.1 установлен штатическим скриптом `get-pip.py` (bootstrap.pypa.io).
   Это не влияет на то, какие пакеты и откуда берутся.
3. **`github.com` из этой сети недоступен** (таймаут соединения), поэтому дистрибутив Temurin
   с Adoptium/GitHub скачать нельзя; Corretto скачан с `corretto.aws`, PyPI доступен.
4. **Файлы состояния сервера**: при работе `HomeTask04Java.jar` в `server/` создаются/изменяются
   `accounts.properties`, `accounts.script`, `accounts.log` (HSQDB + лог). Побочный эффект
   запуска сервера, к исходному коду и тестам отношения не имеет.
5. В README проекта указано требование «Python 3.10+»; проверено на Python **3.14.4** —
   совместимость подтверждена, `javaobj-py3 0.4.4` на 3.14 работает.
6. Известное ограничение самой реализации (описано в `README.md`): `AccountManager.call_register()`
   отвергает нулевой ID сессии; существующая фикстура обходит это warmup-регистрацией на сервере,
   не изменяя ни `src/`, ни проверки в тестах.
